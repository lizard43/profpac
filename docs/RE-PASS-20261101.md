# Professor Pac-Man — Z80, TERSE, graphics and audio RE pass

Date: 2026-11-01 · Branch: `profpac-reassessment-20261031`

## Bank directory decoder recovered

`tools/analyze_question_banks.py` was reconstructed from the surviving
`docs/question_roms.md` layout and the interface used by
`tools/analyze_question_families.py`:

- `BANK_BASE = $4000`, `PPQ_COUNT = 14`.
- Each physical bank must be 16,384 bytes and begins with a little-endian
  root-directory pointer.
- Root contains exactly eight tier pointers.
- Tier buckets consist of a count byte followed by little-endian initializer
  execution addresses.
- Each initializer must lie inside the PPQ window and begin with `RST $08`
  (opcode `$CF`).
- The decoder compares individual bank root addresses, tier bucket counts,
  reference counts, and unique initializer counts against the documented
  ROM inventory, and checks the aggregate 201 references / 130 unique entries.
- CLI supports the original `ARCHIVE` and `--details` forms.

Run:

```sh
python3 tools/analyze_question_banks.py roms/orig/profpac.zip
python3 tools/analyze_question_banks.py --details roms/orig/profpac.zip
```

The decoder is a genuine structural validator, not a permissive stub.

## Native code labels and function comments

### `src/pps1.asm` — reset, bootstrap, inner interpreter

| Address | Recovered label | Demonstrated role |
|---|---|---|
| `$001B` | `COLD_CLEAR_IO_PORT_LOOP` | Clear initial I/O register range |
| `$0053` | `COLD_RAM_PROBE_RESTART` | Reinitialize compare state for memory probe |
| `$0087` | `SCREEN_FAILURE_STROBE_LOOP` | Persistent diagnostic output loop |
| `$00C9` | `CHECKSUM_RETURN_TO_TERSE` | Restore threaded continuation |
| `$00CD` | `CHECKSUM_FINAL_SEGMENT` | Final-ROM checksum decision |
| `$011B` | `ARRAY_INLINE_BASE_FETCH` | Shared inline address step for array primitives |

Function headers were expanded for reset, cold start, switch selection,
checksum, `TERSE_NEXT`, `_BARRAY` and `_ARRAY`.

### `src/pps2.asm` — audio-register execution words

| Address | Recovered label | Effect |
|---|---|---|
| `$2AE1` | `WRITE_INDEXED_IO_REGISTER` | Derive output port from selected sound state and write the value |
| `$2B01` | `SOUND_WRITE_REGISTER_01` | Native register-offset 1 writer |
| `$2B10` | `SOUND_WRITE_REGISTER_02` | Native register-offset 2 writer |
| `$2B1F` | `SOUND_WRITE_REGISTER_03` | Native register-offset 3 writer |
| `$2B2E` | `SOUND_WRITE_REGISTER_PAIR_02_03` | Threaded pair writer |
| `$2B35` | `SOUND_WRITE_REGISTER_04` | Native register-offset 4 writer |
| `$2B44` | `SOUND_WRITE_REGISTER_07` | Native register-offset 7 writer |
| `$2B53` | `SOUND_WRITE_REGISTER_06` | Native register-offset 6 writer |
| `$2B62` | `SOUND_WRITE_REGISTER_05` | Native register-offset 5 writer |
| `$2B71` | `SOUND_WRITE_REGISTER_TRIO_05_07` | Threaded three-register writer |

The native words pop a value through the alternate register set, supply a
constant offset in B to the common indexed writer, and update the cached
sound-chip state at offset 6 plus that register number. The pair/trio words
sequence multiple native register writers. These are exact control-flow
observations; specific waveforms and individual sound effects still require
caller/table tracing.

### `src/pps9.asm` — bank selection and TERSE round control

The `$CEC8` thread now has the semantic label
`SELECT_RANDOM_POPULATED_QUESTION_BANK`. It selects an EPROM with an
`$80`-based selector, writes port `$F3`, and rejects unpopulated bank
windows by testing the root entry against `$FFFF`.
Its helper at `$CEBF` was named
`READ_SELECTED_QUESTION_BANK_STATE`. The
configuration-0 and configuration-1 switching entries at `$D0C9` and
`$D0D4` are also given semantic labels.

## Inline graphics and retained bytes

The PPQ source is **already annotated** with decoded 2-bpp images: four-byte
reference/width/height headers and per-row comments rendering stored pixel
values as `.123` groups. The `tools/analyze_ppq_graphics.py` checker verifies
each encoded row against the corresponding ROM data. Retain this representation.

Not all `DB` blocks are images. Particularly `pps3` and `pps4` contain
mixed geometry, tables, threaded code, and image data. For these regions,
byte-preserving records remain appropriate until their callers and format can
be demonstrated. Reinterpreting a byte range as Z80 or as a bitmap merely to
eliminate `DB` would weaken the RE.

## Remaining TERSE recovery targets

The configuration-0 `pps3` still contains address-derived colon-word names
such as `TERSE_COLON_82E0` and unknown execution tokens (`$3D67`, `$3DE7`).
These should be resolved by tracing their native/cross-ROM callers and the
data records they manipulate, rather than assigning inferred game semantics.

Priority:
1. Recover the precise register roles for the seven sound writers, their
   output-port state table and audio cue callers.
2. Trace `pps3` image/pattern tables from actual TERSE and native references
   before promoting more raw bytes to structured directives.
3. Continue function-level headers for the remaining `pps1` and `pps5`
   routines, with input/output stack effects and caller references.
4. Cross-reference unresolved TERSE execution tokens and colon entries with
   the recovered 1979/1982 dictionary lineage.

## Validation boundary

All native and TERSE label replacements in this pass were address-preserving.
The full source build and exact archive checksum still require execution in a
runtime with `zmac` and the ROM package. No intentional byte changes were
made to any assembly source. The active `temp/` folder was already emptied
in the previous PR cleanup; historical snapshots remain available in Git.

The reference archive SHA-1 and per-ROM SHA-1 checks in `build.sh` are the
required acceptance criteria for subsequent edits.
